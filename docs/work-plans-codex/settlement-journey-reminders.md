# 정산 진행·여정 완성 알림 정책 계획

## 작업 정보

- 대상 repo: `togethertrip-server-notification`
- GitHub Issue: [#40 정산 진행·여정 완성 알림 정책 설계](https://github.com/together-trip/togethertrip-server-notification/issues/40)
- 상태: 승인 전 정책안

## 목표

정산을 미루는 사람을 공개적으로 압박하지 않고, 각 참여자에게 필요한 다음 행동만 전달한다. 정산이 완료되면 여정도 결산이 완성되었다는 결과를 알린다.

## 알림 후보

| 사건 | 수신자 | 다음 행동 |
|---|---|---|
| 정산 생성 | 정산 대상 참여자 | 금액 확인 |
| 금액 확인 완료 | 아직 미확인 참여자 | 금액 확인 |
| 송금 완료 표시 | 수령자 | 수령 확인 |
| 정산 마감 임박 | 미확인·미송금자 | 정산 진행 |
| 전체 정산 완료 | 여행 멤버 | 완성된 여정도 열기 |

## 정책 원칙

- 자기 자신에게 발생한 행동 알림은 보내지 않는다.
- 같은 상태 변경에 대한 중복 알림을 막는다.
- 알림 payload에는 최소한의 여행·정산 정보만 포함한다.
- 딥링크 도착 후 app/main 권한 검증을 다시 수행한다.
- 푸시 실패와 알림함 저장 실패를 구분한다.
- PWA 웹 푸시는 기존 모바일 푸시와 별도 기술 이슈로 둔다.

## 문구 방향

압박보다 행동을 명확히 한다.

- `여행 정산 금액을 확인해주세요`
- `받을 돈 32,400원의 수령 확인이 필요해요`
- `정산이 모두 확인됐어요. 여행 결산을 열어보세요`

미정산자 이름·순위·금액을 전체 멤버에게 공개하지 않는다.

## 제외 범위

- FCM/APNs provider 교체
- 웹 service worker 구현
- 정산 상태 계산 변경
- 공개 리캡 데이터의 내용 결정
- 마케팅 대량 발송

## 문서 동기화 대상

정책 승인 후에만 다음을 갱신한다.

- `docs/api/notification-api.md`
- 알림 타입·문구·딥링크 매핑
- main Outbox 이벤트 계약
- app 알림함·딥링크 처리 계획

## 검증 계획

- 정산 생성자·결제자·부담자·수령자별 수신 대상
- 자기 자신 제외
- 반복 송금 확인 요청 중복 방지
- 마감일 경계와 시간대
- 여행 권한이 없는 딥링크 접근 차단
- 알림함 저장은 성공했으나 푸시가 실패한 경우

구현 시 `./gradlew test`를 실행한다.
